# Инструкция для ИИ-агентов

Прокси предоставляет доступ к сервисам, доступным через OpenVPN, отдельным приложениям на Windows. Адрес по умолчанию — `127.0.0.1:2079`; один порт принимает HTTP и SOCKS5. Системный прокси включать не требуется. Подключение и установка описаны в [README.md](README.md).

## Правила работы

- Используйте прокси только для нужной команды или процесса. Не меняйте системный прокси и глобальную конфигурацию Git без отдельного запроса.
- Не выводите, не копируйте в репозитории и не публикуйте `.ovpn`, логин, пароль, пароль закрытого ключа, токены, заголовки авторизации и содержимое сессий. Файл учётных данных предоставляется владельцем отдельно.
- Не предполагайте, что любой внутренний ресурс доступен: его адрес, права и DNS зависят от профиля и VPN-сервера.
- На Windows вызывайте `curl.exe`, а не `curl`: в некоторых версиях PowerShell `curl` является псевдонимом другой команды. Если `curl.exe` отсутствует в PATH, используйте `$env:windir\System32\curl.exe`.

## Проверка подключения

В PowerShell проверьте HTTP-прокси, не выводя содержимое страницы:

```powershell
& "$env:windir\System32\curl.exe" -sS -o NUL -w "HTTP %{http_code}`n" --max-time 20 --proxy http://127.0.0.1:2079 https://service.servermall.ru/
```

Аналогично через SOCKS5 с разрешением имени на стороне прокси:

```powershell
& "$env:windir\System32\curl.exe" -sS -o NUL -w "HTTP %{http_code}`n" --max-time 20 --proxy socks5h://127.0.0.1:2079 https://service.servermall.ru/
```

Код 200 означает, что HTTP-сервер ответил на запрос; 301 или 302 может означать перенаправление, в том числе на страницу входа. Это не подтверждает авторизацию. Для внутреннего адреса или IP подставьте фактический URL и порт сервиса. `socks5h` позволяет разрешить внутреннее доменное имя в VPN-среде. Для HTTP-прокси имя сервиса также разрешается на стороне прокси.

Если запрос не проходит, проверьте статус службы и журнал по инструкции в README. Для сравнения можно явно обойти прокси с `--noproxy '*'`; не считайте отсутствие прямого доступа ошибкой, если сервис доступен только через VPN.

## Git по HTTPS

Для единичной команды передайте конфигурацию через `-c`, не записывая её глобально. Пример для внутреннего Git-сервера:

```powershell
git -c http.proxy=socks5h://127.0.0.1:2079 ls-remote https://git.na0.ru/GROUP/REPOSITORY.git
```

Подставьте реальный путь репозитория. Альтернатива — `-c http.proxy=http://127.0.0.1:2079`. Используйте существующий безопасный механизм авторизации Git; не помещайте токен в URL или командную строку. Отказ в доступе или запрос учётных данных не означает, что прокси неисправен. При наличии переменных `HTTP_PROXY`, `HTTPS_PROXY` или `NO_PROXY` учитывайте их влияние на конкретный инструмент.

Эти примеры относятся к HTTPS. Git по SSH не использует параметр `http.proxy`; для него нужна отдельная настройка SSH через SOCKS5. Не изменяйте общую конфигурацию SSH без необходимости и проверки.

## Доступ к локальным адресам

Прокси установлен только на `127.0.0.1` Windows. Адреса вроде `10.x.x.x`, имена внутри VPN и порты внутренних сервисов передаются как назначение запроса, например:

```powershell
& "$env:windir\System32\curl.exe" -sS --max-time 20 --proxy http://127.0.0.1:2079 http://10.0.0.10:8080/
```

IP и порт в примере условные. Для HTTPS используйте имя из сертификата и не отключайте проверку TLS только ради успешного теста. Не предполагается поддержка UDP: SOCKS5 в этой реализации поддерживает TCP CONNECT.
